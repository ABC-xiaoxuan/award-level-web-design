# 获奖级网页设计与自检迭代

目标是让清晰的设计概念贯穿内容、排版与交互，同时支持用户完成主要任务。获奖网站是品质参考，不把特效数量或主观评分当成验收证明。

## 1. 先明确任务，再定设计

先阅读相关页面、组件、设计令牌与项目约束，从用户描述和现有文件整理简报：**目标、受众、主要操作、品牌与真实内容、技术及时间约束**。仅在关键缺失信息会改变方案时询问；其他假设简短记录并继续工作。

按任务选择工作范围：

- **新建展示页**：建立概念、字体、色彩、网格和内容节奏，选择一个让人记住的签名时刻。
- **局部打磨**：沿用既有设计系统，解决指定页面的问题；避免扩大改动到全站。
- **产品 UI**：优先流程、信息密度、状态反馈和易用性；品牌表达服务于任务，不强行加入展示页叙事。

用两三句话说明概念与关键取舍。签名时刻可以是静态构图、摄影、排版或一个精心设计的交互，**不要求签名动效**。字体搭配考虑中文覆盖与授权；已有品牌字体和令牌优先复用。配色、字号与间距采用一致的体系，不为“独特”破坏阅读和操作。

检查模板化组合是否适合内容，例如居中大标题、三张等宽卡片、渐变、重复圆角阴影；这些手法可以使用，但应能解释它们如何服务于概念。

## 2. 实现与动效底线

- 使用语义化 HTML，集中维护颜色、字号、间距、圆角、缓动等令牌；沿用项目现有技术和命名。
- 交互元素具有清晰的 `hover`、`focus-visible`、`active` 和适用的 `disabled` 状态；键盘可达，文本对比度达到 WCAG AA。
- 在 **375 / 768 / 1280 / 1920** 宽度检查布局与内容，避免横向滚动、裁切和操作区过窄；必要时补充实际设备宽度。
- 图片预留尺寸，字体使用 `font-display: swap`；不为装饰引入重型依赖。
- **内容默认可见，动效采用渐进增强。** 初始化成功后才添加隐藏或入场状态；JS 失败仍能阅读和操作。
- 动效服务于阅读顺序，通常使用 `transform` / `opacity` 和 180–700ms 的统一缓动。静态设计适合任务时直接采用。
- 实际验证 `prefers-reduced-motion: reduce`：内容直接呈现，清除延迟和错峰，停止非必要连续动画；运行时偏好变化也应生效。
- 超过 5 秒的自动更新或循环内容提供可见的暂停/播放控件；页面隐藏、元素离屏、悬停/聚焦及用户暂停时停止非必要播放。

选用动效或 JS 计时器时阅读 [references/motion-patterns.md](references/motion-patterns.md)，包含初始化失败回退和动态偏好监听模板。

## 3. 渲染、检查、批量优化

必须查看真实渲染结果。使用 Python 3.10+ 与 Playwright 的辅助脚本，无需单独安装 Node.js；脚本仅在浏览器内执行必要的 DOM / PerformanceObserver JavaScript。

```bash
uv run <skill目录>/scripts/shoot.py <页面URL或HTML文件> --audit --sections '#work,.pricing' --out shots
```

安装、浏览器选择、`--full` / `--perf` / `--axe`、就绪条件、状态脚本和报告结构见 [references/verification.md](references/verification.md)。检查动效时添加 `--reduced-motion`，分别采样 normal 与 reduce；交互使用 `--states` 加明确的 `expect`，然后补人工键盘与操作检查。

每一轮：

1. **截图与审计**：检查四个宽度的首屏、关键区块和关键状态。自动结果是缺陷线索：确认 error 并优先修复；warning 逐条判断和记录，未知或未检查不能算通过。
2. **人工复核**：读取 [references/review-checklist.md](references/review-checklist.md)，检查排版、留白、视觉层级、色彩、动效、微交互、响应式、原创性。可用 1–10 分辅助比较，必须指出具体问题与改法；不强制八项达到 9 分。
3. **按影响批量修改**：先修阻断操作、内容不可见和整体层级问题，再处理间距、断行与过渡；一轮集中改完再截图，避免逐处重复采样。

默认 2 轮、最多 3 轮；快速原型做 1 轮，明确要求深度打磨时可增加。第 3 轮针对回归或仍影响任务的具体问题，不为提升自评分继续改动。

**停止条件**：关键流程实测通过、已确认的阻断缺陷和质量底线问题已处理、四个视口及相关状态完成截图复核，剩余 warning / 未检查项 / 素材限制均有真实记录。预算或环境受限时交付现有结果，注明未完成验证和风险，不把代码审查称为浏览器验收。

## 4. 交付

简短说明设计概念与关键取舍、完成的改动、实际验证的宽度与状态、自检轮次及主要修正。附截图或报告路径，记录剩余问题与需要的真实文案、摄影、品牌资产等。评分仅在有比较价值时提供；自动扫描、单次性能样本和截图不能代替完整交互及无障碍验证。
