# 八维度自检清单

每个维度给 1–10 分。9 分的含义：放在 Awwwards 当日提名里不会被这一项拖后腿。低于 9 分时，写出具体问题和修改方案。

标 **⚠ 常见坑** 的条目是实际做页面时反复出现、而且只看代码很难发现的问题，每一轮都要专门检查。

标 **[自动]** 的条目由 `scripts/audit.js` 检查（`shoot.mjs --audit` 会在每个宽度运行它）。有 audit 报告时，以报告为准，把人工精力留给其他条目。

## 1. 排版 Typography
- 字号是否来自统一的比例尺？展示字号和正文之间有没有足够的戏剧性对比？
- 行高：大标题约 0.95–1.15，正文约 1.5–1.75（中文正文可略高）。字距：大标题通常需收紧，全大写小字需放宽。
- 正文行长约 45–75 个西文字符 / 25–40 个汉字。
- **[自动]** 有没有孤字、难看的断行、标题最后一行只剩一个词？（可用 `text-wrap: balance` / `pretty`）
- 字体搭配是否服务于概念？字重层次是否清晰（不要只有 400 和 700）？
- **⚠ 常见坑：中文在词中间断行。** 浏览器可以在任意两个汉字之间换行，大标题和引文很容易出现"房/间""东/西"这种拆词。逐个检查每个宽度下的大字号中文：
  - 标题：用 `<br>` 明确断在语义停顿处（逗号后、短语间）。
  - 长句引文：把每个短语包进 `<span style="white-space:nowrap">`，短语之间放 `<wbr>`。只用 nowrap 不加 `<wbr>` 时，Chrome 不会在相邻两个 nowrap 元素之间换行，整句会溢出。
  - `text-wrap: balance` 配合短语分组时，可能把中文行切得很短（每行 4–6 字），手机上应改回 `wrap`。
  - 窄屏预估：每行字数 ≈ 容器宽 ÷ 字号。如果最后一行只剩 1–2 个字，就缩小字号或改断句。
- **⚠ 常见坑 [自动]：中文字体回退。** 西文等宽字体或展示字体不含汉字。`font-family` 栈里如果不显式加中文字体（如 `"JetBrains Mono","Noto Sans SC",monospace`），中文会回退到系统字体，Windows 上常常是宋体，和设计格格不入。凡是可能出现中文的字体栈都要检查。

## 2. 留白 Whitespace
- 间距是否都来自同一套刻度？有没有随手写的 13px、27px？
- 区块之间的大留白是否足够大胆？元素是否在"呼吸"，还是挤在一起？
- 相关元素靠近、无关元素远离（格式塔接近原则）是否成立？
- 留白是否有节奏变化，而不是每个 section 都一样的上下 padding？
- **⚠ 常见坑：简写属性覆盖容器边距。** 同一个元素既有 `.wrap`（左右内边距）又有 `.hero` / `.section` 时，后者写 `padding: 64px 0` 会把左右内边距清零，内容贴着屏幕边缘。区块的上下间距一律用 `padding-block`，容器左右用 `padding-inline`。
- **⚠ 常见坑：选择器优先级。** `footer{padding:…}` 这种元素选择器会被 `.wrap` 这种类选择器覆盖，看起来"写了没生效"。
- **⚠ 常见坑：浏览器默认样式。** `<figure>` 默认有约 40px 的左右外边距，`<blockquote>`、`<ul>`、`<h1>`–`<h6>` 也都有默认外边距，要显式归零。

## 3. 视觉层级 Hierarchy
- 眯眼看截图：第一眼、第二眼、第三眼分别落在哪里？是否符合内容优先级？
- 每屏是否只有一个主角？主 CTA 是否一眼可辨，次要操作是否确实"次要"？
- 尺寸、字重、颜色、位置这些层级手段是否用得克制，没有处处都在喊？
- 首屏有没有大块无意义的空洞（例如标题只占左半边、右上角整块空着）？可以放大字号铺满宽度，或者用错位构图（第二行右对齐）来平衡。

## 4. 色彩 Color
- 调色板是否克制、统一，由变量驱动？强调色是否只出现在真正需要注意的地方？
- **[自动]** 文本对比度是否 ≥ 4.5:1（大字 ≥ 3:1）？注意序号、页脚、元信息这类"次要文字"：为了显得高级而调得很淡，是最常见的不达标原因。
- 中性色是否带有微妙色倾（而不是纯 #000 / #fff / 纯灰）以增加质感？
- 如果有暗色模式，是否单独调过，而不是简单反色？
- 暗色背景上的装饰线条或纹理，在真实屏幕上是否看得见？透明度低于约 10% 时，往往等于不存在。

## 5. 动效 Motion
- 每个动效是否有目的（引导注意、表达因果、建立空间关系），而不是装饰性的"到处淡入"？
- 缓动曲线和时长是否统一成一套体系？入场是否有恰当的错峰（stagger）？
- 滚动驱动的动画是否流畅（60fps，无布局抖动）？是否只动 transform/opacity？
- **[自动]** `prefers-reduced-motion` 下是否优雅降级？（脚本只检查有没有这条规则，降级效果仍需人工看）
- **⚠ 常见坑：Canvas / 跟随指针的效果。**
  - 初始状态：指针位置的初始值如果是 -9999 再做缓动，第一次进入时效果会从屏幕外"扫"进来。首次进入应直接跳到指针位置，离开时重置。
  - 高亮要局部化：按"离指针近"给整条线或整个元素换色，结果往往是大片同时变色。应该用以指针为中心的径向渐变作为描边或填充。
  - 位移函数要连续：`(dy>=0?1:-1)*g` 这种符号跳变会把线条撕成垂直断口，应使用 `Math.tanh(dy/k)` 这类平滑函数。

## 6. 微交互 Micro-interactions
- 链接、按钮、卡片、输入框：hover / focus-visible / active / disabled 状态是否都设计过？
- 反馈是否即时且有质感（例如按钮按下的轻微缩放、链接下划线的生长动画、光标跟随）？
- 表单校验、加载、成功、空状态是否都考虑到了？
- 键盘导航时焦点环是否清晰且与设计风格一致？
- 跟随指针的读数（坐标、数值）在页面滚动时是否同步更新，而不只是响应鼠标移动？

## 7. 响应式 Responsive
- 在 375 / 768 / 1280 / 1920 宽度下截图逐一检查：有没有横向滚动、溢出、重叠、过小的点击区（< 44px）？**[自动]** 会报告溢出和点击区，重叠仍需人工看截图。
- 移动端是不是"重新构图"了，而不是桌面版简单堆叠缩小？
- 字号是否用 `clamp()` 平滑缩放？超宽屏下内容是否有合理的最大宽度？
- 触屏设备上依赖 hover 的信息是否有替代方式（例如点击展开）？
- **⚠ 常见坑 [自动]：被 `overflow-x: clip` 掩盖的溢出。** body 上加了 clip 以后，页面不会横向滚动，但溢出的内容会被直接切掉，截图里不一定看得出来。每个宽度都用脚本检查一遍 `document.documentElement.scrollWidth`，并列出右边界超过视口的元素：
  ```js
  [...document.querySelectorAll('body *')].filter(e => e.getBoundingClientRect().right > innerWidth + 1)
  ```
- **⚠ 常见坑：缩放后的 SVG 文字。** 按 viewBox 等比缩放的图表，在手机上标注文字可能只剩 6px。小屏要单独放大 SVG 内的字号，或者精简标注。
- **⚠ 常见坑：12 栏网格在手机上的窄列。** 桌面上合理的 `grid-column: 1/4`，在 375 宽下只有约 80px，Logo、标签、编号会被挤成多行或和标题重叠。手机断点要逐个元素重新分配列跨度。
- **⚠ 常见坑：媒体查询里的规则被后面的规则覆盖。** 在断点里设置的显示/隐藏，如果同一条规则在源码中写在断点之后，断点就失效了。检查计算后的样式（`getComputedStyle`），不要只看源码。
- 批量查找替换 CSS 时，同一个选择器片段可能同时出现在基础样式和媒体查询里。替换后要检查每一处匹配的结果，否则会悄悄改坏断点里的规则。

## 8. 原创性 Originality
- 遮住 logo 后，这个页面能和一个现成模板区分开吗？
- 有没有至少一个"签名时刻"让人想截图分享？
- 设计概念是否贯穿全页，还是只在首屏出现、后面退化成通用版式？
- 有没有落入"AI 模板脸"（紫蓝渐变、三卡片、emoji 图标、全站同一圆角阴影）？若有，是否能说出它服务于概念的理由？

## 渲染验证的注意事项

截图看到的东西不一定就是页面的真实状态，判断问题之前先排除这些干扰：

- **滚动揭示动画还没结束**：元素发灰、半透明，往往只是过渡还在进行。等动画时长 + 余量后再截，或者用 `getComputedStyle(el).opacity` 确认。
- **浏览器窗口被隐藏或在后台**：`requestAnimationFrame` 会暂停，依赖 rAF 的缓动、Canvas 效果看起来"没反应"。这时用截图强制渲染一帧，或者在可见状态下再测，不要误判成代码有问题。
- **模拟悬停不触发事件**：自动化工具的 hover 在设备模拟下可能不会派发 `pointermove`。用 `el.dispatchEvent(new PointerEvent('pointermove', {...}))` 或 `mouseenter` 来验证交互逻辑。
- **截图缩放产生的色边**：缩小后的截图里，中文笔画可能带蓝色或橙色的伪色。怀疑字体或颜色有问题时，裁剪原图放大确认。
- **audit 的对比度误报**：如果元素正处于颜色过渡中，读到的颜色是中间值。audit.js 已跳过正在运行动画的元素，但对比度读数异常低（例如 1.0:1）时，仍要先确认是不是这种情况。
- **网页字体还没加载完**：截图前等待 `document.fonts.ready`。滚动到新区域后再等一次，因为中文网页字体是按字符子集分批加载的。
- **无头浏览器截图**：`--virtual-time-budget` 有时等不到网页字体加载完成，会截出空白页。更可靠的做法是通过 DevTools 协议导航、等待 load 和 `fonts.ready`、再滚动截图。`scripts/shoot.mjs` 已经这样实现。
- **本地文件路径过长**：Windows 上超过约 260 个字符的路径，Chrome 打不开 `file://`。把文件复制到较短的路径，或者用本地 http 服务打开。
