# 获奖网站深度拆解

深度拆解的目标是提取可迁移的判断原则，不是复制页面。它适合在概念还没有确定时使用，也可以单独用于回答“这个站为什么有效”。

## 两条护栏

- **原则，不是像素。** 可以迁移“制作公司的产品就是影像，所以首屏先展示 reel”这类推理。不能迁移具体网格、颜色、缓动、hero 构图。
- **证据，不是断言。** 每个技术事实都要带可重跑的 URL、命令或浏览器观察。无法确定时写“未知”，不要猜。

## 先收集证据

先打开真实页面和奖项页面，再分析截图。可用以下命令做基础指纹：

```bash
curl -s -L --max-time 30 "<url>" \
  | tr '>' '>\n' \
  | grep -oiE "wp-content|wp-json|_next/static|__nuxt|astro-|gsap|lenis|three" \
  | sort | uniq -c | sort -rn
```

再用浏览器记录网络资源、脚本、桌面和移动截图。记录无法确定的内容。Nominee 的页面描述不等于评委意见，不要把制作方的自述写成评委结论。

## 五个独立角度

| 角度 | 要回答的问题 | 证据 |
| --- | --- | --- |
| 概念 | 一句话是什么，媒介是否匹配主题 | 页面文案、奖项描述 |
| 签名时刻 | 唯一的互动是什么，移动端和 reduced-motion 如何处理 | 实际操作、浏览器测试 |
| 美术方向 | 字体、色彩、网格、间距和令牌是什么 | computed styles |
| 动效语言 | 缓动、时长、编排和滚动策略是什么 | 脚本、DevTools |
| 结构与内容 | 导航、索引、页面类型和内容更新方式是什么 | HTML、CMS 指纹 |

签名时刻要通过一个问题：换一套视觉语言后，它仍然成立吗？成立的是原则，不成立的只是布局。

## Idea card 格式

每个站点写一个 `references/inspiration/<slug>.md`，包含：

```yaml
---
site: 示例站点
url: https://example.com/
award_type: Nominee
studio: 未知
stack: [Astro, GSAP]
verified: 2026-10-15
---
```

正文按以下顺序：

1. 为什么有效，分别对应 Design、Usability、Creativity、Content。
2. 证据，列出命令和关键观察。
3. 三条可迁移原则，每条说明它为什么在当前站点成立。
4. 什么不能迁移，明确写出属于该站的布局、颜色和效果。
5. Gap check，说明当前 skill 已覆盖什么，真正缺少什么。

三条原则是上限。卡片如果足以重建原站，就说明写成了模板。

## 什么时候不改仓库

多数深度拆解最后不会新增 reference，这是正常结果。已有参考覆盖时，只把卡片加入 inspiration；发现真实缺口时，才提交新的方法文档。卡片必须有 `verified` 日期，过几个月应重新采证。

## 常见错误

- 只看奖项截图，不打开真实页面。
- 把 Nominee 当成 SOTD。
- 把“评委喜欢”写在没有公开评语的页面上。
- 复制精确的颜色、间距和 easing。
- 没有“什么不能迁移”一节。
